# Template: Ruby project (Rails app or gem)

Use when the detector reports `primary: "ruby"`: a `Gemfile` at the root. Covers Rails apps, Sinatra or other Rack apps, and gems with a `.gemspec`.

## Detection signals
- `primary: "ruby"`, `packageManager: "bundler"`.
- `frameworks` lists `rails` with its version when the Gemfile names it. A `.gemspec` at the root with no `rails` entry means a gem.
- `commands` is empty unless a Makefile or CI workflow supplies it. Derive commands yourself and verify each file exists before writing it: `bin/rails`, `bin/rspec`, `bin/rubocop`, `bin/setup`, `bin/dev`, `Rakefile`, `spec/`, `test/`. Prefer a binstub over `bundle exec` when the binstub exists.
- Test runner: `spec/` with `rspec` in the Gemfile means RSpec. `test/` means Minitest (`bin/rails test` in Rails, `bundle exec rake test` in a gem).
- Lint and format: `rubocop`, `rubocop-rails-omakase` or `standard` in the Gemfile. Security: `brakeman` and `bundler-audit` only if listed.
- Ruby version: `.ruby-version`, `.tool-versions` or the Gemfile `ruby` line.
- Rails extras to check by file: `config/deploy.yml` (Kamal), `config/credentials/`, `db/structure.sql` vs `db/schema.rb`.

## AGENTS.md
- **Commands**: setup (`bin/setup` or `bundle install`), dev (`bin/dev` or `bin/rails server`), test (all, one file, one line: `bin/rails test test/models/user_test.rb:12` or `bundle exec rspec spec/models/user_spec.rb:12`), lint, security scans if present, `bin/rails db:migrate` and `db:test:prepare` for Rails.
- **Repo map**: for Rails, only the unusual parts: engines, `app/services`, `app/jobs`, `app/components`, `lib/`. Do not list the standard Rails directories. For a gem: `lib/<name>/`, `spec/` or `test/`, `exe/`.
- **Conventions worth writing**: where business logic lives (models, service objects, concerns); background job adapter and idempotency expectations; authorization library; how views are built (ERB, ViewComponent, Hotwire) when it is not the default; factories vs fixtures; whether `db/structure.sql` or `db/schema.rb` is the source.
- **Version notes**: pull from `knowledge/ruby.md` for the detected Ruby, Rails and test gem versions. Defaults and generators differ between Rails versions, so do not write them from memory.
- **Boundaries**: never read `config/master.key` or files in `config/credentials/`; never print decrypted credentials. Existing migrations are not edited after merge; add a new one. `db/schema.rb` and `db/structure.sql` are regenerated by running migrations, not hand-edited. `Gemfile.lock` changes through bundler only. For a gem, changing public methods is an API change.

## CLAUDE.md
`@AGENTS.md` on the first line. Claude-only lines only if the user has them.

## .claude/settings.json
Shown for a Rails app with RSpec and RuboCop. Keep only the lines whose tools exist. For Minitest use `Bash(bin/rails test *)`. For a gem use `Bash(bundle exec rake *)` only if the Rakefile has no release or deploy task you would not run; otherwise list tasks.
```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": [
      "Bash(bundle install)",
      "Bash(bundle exec rspec *)",
      "Bash(bin/rails test *)",
      "Bash(bin/rails db:migrate)",
      "Bash(bin/rails db:test:prepare)",
      "Bash(bin/rails generate *)",
      "Bash(bin/rubocop *)",
      "Bash(git add *)",
      "Bash(git commit *)"
    ],
    "ask": ["Bash(git push *)", "Bash(bin/rails console*)"],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(git push --force *)",
      "Bash(git push -f *)",
      "Bash(git reset --hard *)",
      "Bash(gem push *)",
      "Bash(bin/rails db:drop*)",
      "Bash(bin/rails db:reset*)",
      "Bash(bin/rails db:migrate:reset*)",
      "Bash(bin/rails db:schema:load*)",
      "Bash(bin/rails credentials*)",
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./config/master.key)",
      "Read(./config/credentials/*.key)",
      "Read(./**/*.pem)",
      "Read(~/.gem/credentials)"
    ]
  }
}
```
- Never add `Bash(bin/rails *)`. It includes `runner` and any `db:` task you did not deny.
- Add `Bash(bundle exec rubocop *)` or `Bash(bundle exec standardrb *)` instead of `bin/rubocop` when there is no binstub. Add `Bash(bin/brakeman *)` and `Bash(bundle exec bundler-audit *)` only if those gems are listed.
- If `config/deploy.yml` exists, deny `Bash(kamal deploy*)` and put `Bash(kamal *)` in `ask`.
- `Read(./.env.*)` also blocks `.env.example`. When the detector's `env.files` lists an example file, deny the real env files by name instead (for example `Read(./.env.local)`, `Read(./.env.production)`) so the example stays readable.

## Formatter hook (optional)
Only when `rubocop` or `standard` is in the Gemfile and the user says yes. Needs `jq`.
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path | select(endswith(\".rb\"))' | xargs -r bundle exec rubocop -a"
          }
        ]
      }
    ]
  }
}
```
For Standard use `bundle exec standardrb --fix`. RuboCop exits non-zero when offenses remain; that is a notice, not a block. Without `jq`: `node -e "let s='';process.stdin.on('data',d=>s+=d).on('end',()=>{const f=JSON.parse(s).tool_input.file_path||'';if(f.endsWith('.rb'))require('child_process').spawnSync('bundle',['exec','rubocop','-a',f])})"`

## Path-scoped rules
Only for directories with real conventions. Mirror rules with `node "${CLAUDE_SKILL_DIR}/scripts/sync-rules.mjs" --targets <tools>` if the user picked other agents.
- `db/migrate/**`: add a new migration, never edit a merged one; make it reversible; large-table or Postgres index rules if the repo uses `strong_migrations` or documents them. Add when more than a few migrations exist.
- `app/models/**` or `app/services/**`: only when the README or docs state where logic belongs or a base class to inherit.
- `spec/**` or `test/**`: factories vs fixtures, shared contexts, tags that gate slow tests. Add when the suite is large enough to have its own rules.
- `app/controllers/**`: authorization pattern (`authorize` calls, `before_action` conventions) when the app enforces one.

## Reviewer subagent
These are candidate checks, not defaults. Keep a line only when a repo fact backs it (lint or type config, a documented rule, a hard rule, a detected version), and grep the repo first: if the code already uses a pattern on purpose, drop the line or scope it with the exception.

`.claude/agents/ruby-reviewer.md`, frontmatter `name: ruby-reviewer`, `description: Reviews Ruby and Rails changes for unsafe queries, mass assignment, N+1 queries, unsafe migrations and swallowed errors. Use after editing .rb or .erb files.`, `tools: Read, Grep, Glob`.
1. Strong parameters on every controller action that writes. No `params.permit!`.
2. SQL built with string interpolation in `where`, `order`, `find_by_sql` or `execute`. Use bind parameters.
3. N+1: loops over associations without `includes`, `preload` or `eager_load`.
4. `html_safe`, `raw` or `sanitize: false` on user input in views.
5. Authorization: new controller actions without the app's auth check; `skip_before_action` added without a reason.
6. Migrations: reversible (`change` or both `up` and `down`), new indexes on large tables use the concurrent form the repo documents, no model code inside the migration.
7. `update_all`, `delete_all` and `update_column` skip validations and callbacks. Flag when the skip is not intended.
8. `rescue => e` or `rescue Exception` that swallows the error; callbacks (`after_save`) that do network calls or enqueue without `after_commit`.
9. Background jobs are idempotent and take ids, not objects. `Time.now` where the app uses `Time.current`.
10. Left-over `binding.irb`, `debugger`, `puts`, `focus: true` or `fit` in specs.

## Skills
- `release`: for a gem, when a `version.rb` (or the gemspec) has a version and a changelog exists. Bump, update changelog, run tests and lint, tag. Do not include `gem push` or `rake release` unless the repo already automates it. Rails apps usually have no version file; skip it.
- `db-migrate`: Rails apps with migrations, when the repo's flow has more than one step (generate, review the file, migrate, check the schema diff, run tests).
- `deploy`: only if `config/deploy.yml` exists and the README documents extra steps. Ask the user first; default is to skip.

## .worktreeinclude
List only entries in `env.gitignored` (`.env`, `.env.local`, `.claude/settings.local.json`, `CLAUDE.local.md`, `.mcp.json`). Rails also gitignores `config/master.key`; list it only if the user agrees in the plan step, because it copies a secret into every worktree. Add `config/database.yml` only if it is gitignored. Do not list `node_modules/`, `tmp/` or `log/`. Skip the file when the list is empty.

## What NOT to generate
- No `Bash(bin/rails *)` or `Bash(bundle exec *)` wildcards.
- No rules that restate RuboCop or Rails conventions.
- No `output-styles/`, `commands/` or `agent-memory/`.
- No `Bash(*)`, no `defaultMode` of `auto` or `bypassPermissions`.
