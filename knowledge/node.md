## Version notes
- **Node <= 20**: Node 20 is EOL (2026-04-30) and 18 is older. Do not write `node-version: 20` or `18` in CI, Dockerfiles or `engines` for new work. Use 24 or 22, and 26 once it is LTS. Do not target 25, it was Current-only and is EOL. [source](https://raw.githubusercontent.com/nodejs/Release/main/schedule.json)
- **Node >= 22.18 (or 23.6)**: type stripping is on by default, so `node file.ts` runs erasable TypeScript with no `tsx` or `ts-node`. It is Stable since 24.12 and 25.2. Turn it off with `--no-strip-types`. [source](https://raw.githubusercontent.com/nodejs/node/main/doc/api/typescript.md)
- **Node type stripping (any version)**: it does no type checking and ignores `tsconfig.json`, so `paths` and JSX settings do nothing. `.tsx` is unsupported. Imports need the real extension (`./file.ts`). `enum`, runtime `namespace`, constructor parameter properties and `import x = require()` fail. For these projects use `target: esnext`, `module: nodenext`, `erasableSyntaxOnly`, `verbatimModuleSyntax` and `rewriteRelativeImportExtensions`. [source](https://raw.githubusercontent.com/nodejs/node/main/doc/api/typescript.md)
- **Node >= 26**: `--experimental-transform-types` is removed, so write erasable syntax only. Temporal is on by default, `http.Server.prototype.writeHeader()` is removed (use `writeHead`), and `module.register()` is deprecated at runtime. [source](https://raw.githubusercontent.com/nodejs/node/main/doc/changelogs/CHANGELOG_V26.md)
- **Node >= 25**: Corepack is no longer bundled. `corepack enable` fails on a fresh install. Run `npm i -g corepack` first, or install pnpm or Yarn another way. Yarn Berry comes from Corepack or `yarn set version`; `npm i yarn` installs Classic 1.22. [source](https://raw.githubusercontent.com/nodejs/corepack/main/README.md)
- **Deno >= 2.9**: `Deno.serve` no longer compresses responses by default; opt in. `deno install` honors a `minimumDependencyAge` setting. [source](https://raw.githubusercontent.com/denoland/deno/main/Releases.md)
- **typescript >= 7.0**: `npm i typescript` installs the native compiler and the command is `tsc`. Drop `@typescript/native-preview` and the `tsgo` command, which were only the preview names. Build mode, project references, watch and declaration emit are done. [source](https://raw.githubusercontent.com/microsoft/typescript-go/main/README.md)
- **typescript >= 7.0 with tooling**: the programmatic API is not ready and the language service is still in progress. typescript-eslint 8.71.1 allows `typescript >=4.8.4 <6.1.0`, so it does not support TS 7. Keep a TS 6 install for lint tooling, or use `@typescript/typescript6`, which ships a `tsc6` binary and the 6.0 JS API. [source](https://registry.npmjs.org/@typescript/typescript6)
- **typescript >= 6.0**: `strict` is true by default, `module` defaults to `esnext` and `target` to the current-year ES version. `rootDir` is the tsconfig directory, no longer inferred, so set `"rootDir": "./src"` if output lands in `dist/src/`. `types` defaults to `[]`: write `"types": ["node"]` (plus `"jest"`, `"bun"` and so on) or you get "Cannot find name 'process'". [source](https://raw.githubusercontent.com/microsoft/TypeScript-Website/v2/packages/documentation/copy/en/release-notes/TypeScript%206.0.md)
- **typescript >= 6.0**: these are deprecated, and TS 7 does not support them: `target: es5`, `moduleResolution: node`/`node10`, `baseUrl`, `esModuleInterop: false`, `allowSyntheticDefaultImports: false`, `alwaysStrict: false`, `module: amd|umd|systemjs`. Use `nodenext` for Node and `bundler` for bundlers and Bun. Delete `baseUrl` and put the prefix in `paths` values (`"@app/*": ["./src/app/*"]`). Write `import express from 'express'`, not `import * as express`. [source](https://raw.githubusercontent.com/microsoft/TypeScript-Website/v2/packages/documentation/copy/en/release-notes/TypeScript%206.0.md)
- **typescript >= 5.8**: `erasableSyntaxOnly` errors on enums, runtime namespaces and parameter properties. With `verbatimModuleSyntax`, write `import type { X }` for types. Under `nodenext` do not write extensionless relative imports. [source](https://raw.githubusercontent.com/microsoft/TypeScript-Website/v2/packages/documentation/copy/en/release-notes/TypeScript%205.8.md)
- **pnpm >= 10**: dependency lifecycle scripts do not run by default. Allow packages in `allowBuilds` (a map like `esbuild: true`) or run `pnpm approve-builds`. Do not set `dangerouslyAllowAllBuilds`. [source](https://raw.githubusercontent.com/pnpm/pnpm.io/main/docs/supply-chain-security.md)
- **pnpm >= 11**: needs Node >= 22. `onlyBuiltDependencies`, `neverBuiltDependencies`, `ignoredBuiltDependencies` and `ignoreDepScripts` are removed; use `allowBuilds`. `.npmrc` is read for auth and registry only. Put all other settings (overrides, `patchedDependencies`) in `pnpm-workspace.yaml` as camelCase keys, not in the `pnpm` field of `package.json`. Env vars are `pnpm_config_*`. [source](https://raw.githubusercontent.com/pnpm/pnpm.io/main/blog/releases/11.0.md)
- **pnpm >= 11**: new defaults are `minimumReleaseAge: 1440` (minutes; a package published less than a day ago will not resolve, so a just-released version can fail to install), `blockExoticSubdeps: true`, `strictDepBuilds: true`. Script names `clean`, `setup`, `deploy` and `rebuild` now shadow built-in commands. `pnpm ci` is new. Codemod: `pnpx codemod run pnpm-v10-to-v11`. [source](https://raw.githubusercontent.com/pnpm/pnpm.io/main/blog/releases/11.0.md)
- **pnpm >= 12**: use `--no-frozen-lockfile`, not `--frozen-lockfile false`. Unknown keys in `pnpm-workspace.yaml` are reported, as an error when the pnpm version is pinned and satisfied. Git dependencies resolve over HTTPS. [source](https://raw.githubusercontent.com/pnpm/pnpm.io/main/blog/releases/12.0.md)
- **pnpm workspaces**: declare packages and `catalog:` / `catalogs:` in `pnpm-workspace.yaml` and reference them as `"react": "catalog:"`. Use `workspace:*` between packages. In Docker, copy `pnpm-workspace.yaml` before `pnpm install`. [source](https://raw.githubusercontent.com/pnpm/pnpm.io/main/docs/catalogs.md)
- **npm >= 12**: dependency lifecycle scripts are blocked unless the root `package.json` allows them with `allowScripts`. After install run `npm install-scripts approve`, then `npm rebuild`. `allow-git` and `allow-remote` default to `none`, so git and tarball-URL dependencies fail until set. Unknown CLI flags throw. `npm-shrinkwrap.json` and `npm shrinkwrap` are removed; use `package-lock.json`. `npm adduser` is gone; use `npm login`. Node 26 bundles npm 11, so npm 12 is a separate install and needs Node `^22.22.2 || ^24.15.0 || >=26`. [source](https://raw.githubusercontent.com/npm/cli/latest/CHANGELOG.md)
- **eslint >= 10**: only flat config works. `.eslintrc*`, `ESLINT_USE_FLAT_CONFIG=false` and `eslint-env` comments are gone. Config is found by walking up from each linted file. Needs Node >= 20.19, 22.13 or 24. Codemod: `npx codemod @eslint/v9-to-v10`. With typescript-eslint use `defineConfig` from `eslint/config` with `extends: [js.configs.recommended, tseslint.configs.recommended]` in `eslint.config.mjs`. Do not use `tseslint.config()` or install `@typescript-eslint/parser` and `-plugin` separately. [source](https://raw.githubusercontent.com/eslint/eslint/main/docs/src/use/migrate-to-10.0.0.md)
- **Biome >= 2**: use `files.includes` (a glob array, `!` negates) instead of `include` and `ignore`; run `biome migrate --write`. Globs resolve from the config file. Oxlint runs type-aware rules and JS plugins; `oxfmt` is still 0.x, so Prettier stays the stable formatter. [source](https://raw.githubusercontent.com/biomejs/biome/main/packages/@biomejs/biome/CHANGELOG.md), [Oxlint](https://raw.githubusercontent.com/oxc-project/oxc/main/apps/oxlint/CHANGELOG.md)
- **express >= 5**: Express 5 is `latest`; 4 is `latest-4`. Bare `*` routes are invalid under path-to-regexp v8, so write `/*splat`. Inline regex like `/:id(\d+)` is unsupported. Rejected promises from async handlers reach the error handler, so drop the `try/catch` plus `next(err)` wrapper. Codemod: `npx codemod@latest @expressjs/v5-migration-recipe`. [source](https://expressjs.com/en/guide/migrating-5)
- **fastify >= 5**: needs Node >= 20. Schemas must be full JSON Schema; shorthand property maps are rejected. `reply.redirect(url, code)` has the new argument order. `request.connection` is removed (use `request.socket`) and so is `reply.getResponseTime()` (use `reply.elapsedTime`). [source](https://raw.githubusercontent.com/fastify/fastify/main/docs/Guides/Migration-Guide-V5.md)
- **Release candidates on npm tags**: Hono 5 (`5.0.0-rc.0`, tag `next`) and Drizzle 1.0 (`1.0.0-rc.x`, tag `rc`) are not stable. Stay on `hono@4` and Drizzle 0.45 unless the project already uses the RC. [source](https://registry.npmjs.org/hono)
- **trpc >= 11**: needs TypeScript >= 5.7.2. Install `@trpc/*@^11` with `@tanstack/react-query@^5`. `transformer` moves into the link (`httpBatchLink({ transformer })`). Subscriptions use `httpSubscriptionLink` and return an `AsyncGenerator`, not an Observable. [source](https://raw.githubusercontent.com/trpc/trpc/main/www/docs/migration/migrate-from-v10-to-v11.mdx)
- **zod >= 4**: the `zod` root import is v4 (v3 is at `zod/v3`). Use `z.email()`, `z.uuid()`, `z.url()` instead of `z.string().email()`. Use `{ error: ... }` for messages, not `message`, `invalid_type_error` or `required_error`. Use `z.strictObject()` and `z.looseObject()` instead of `.strict()` and `.passthrough()`, `.extend()` instead of `.merge()`, `z.enum()` instead of `z.nativeEnum()`, and `z.treeifyError()` instead of `.format()` and `.flatten()`. `z.record()` takes two arguments. [source](https://raw.githubusercontent.com/colinhacks/zod/main/packages/docs/content/v4/changelog.mdx)
- **prisma >= 7**: use generator `provider = "prisma-client"` with a required `output` path, and import from that path, not `@prisma/client`. `PrismaClient` needs a driver adapter such as `@prisma/adapter-pg`. Datasource URLs move from `schema.prisma` to `prisma.config.ts` (`defineConfig` from `prisma/config`). `.env` is not auto-loaded (import `dotenv/config`; Bun loads it itself). `$use` middleware is removed; use Client Extensions. Needs Node >= 20.19 and TS >= 5.4. [source](https://raw.githubusercontent.com/prisma/docs/main/apps/docs/content/docs/guides/upgrade-prisma-orm/v7.mdx)
- **prisma 8 RC**: the `prisma` package `latest` tag is `8.0.0-rc.22`, with 7.10.0 under `prev`. A bare `npx prisma` or `npm i prisma` outside an existing install can pull the RC. Pin `prisma@7` and `@prisma/client@7` for production. [source](https://registry.npmjs.org/prisma)
- **playwright >= 1.60**: `Locator.ariaRef()`, the `logger` option and `videosPath` / `videoSize` are removed; use `recordVideo`. 1.59 removed `@playwright/experimental-ct-svelte`. In 1.64, JSX in test files follows the tsconfig `jsx*` options. [source](https://raw.githubusercontent.com/microsoft/playwright/main/docs/src/release-notes-js.md)
- **turbo >= 2**: `turbo.json` uses `tasks`, not `pipeline`. Migrate 1.x with `npx @turbo/codemod migrate`. [source](https://registry.npmjs.org/@turbo/types/-/types-2.11.7.tgz)
- **changesets >= 3.0**: `changeset tag` is now `changeset git-tag`. `changeset version` exits 1 when no changesets exist. The `prettier` option in `.changeset/config.json` is replaced by `format`. Needs Node `^22.11 || ^24 || >=26`. [source](https://raw.githubusercontent.com/changesets/changesets/main/packages/cli/CHANGELOG.md)
- **vitest >= 5**: needs Node >= 22.12 and Vite >= 6.4. `vite` is now a peer dependency, so Yarn users run `yarn add -D vite`. `clearMocks` defaults to true. `vi.mock`, `vi.unmock` and `vi.hoisted` must be top level. Un-awaited async assertions fail the test, so `await expect(...).resolves` and `expect.poll`. `test.sequential` is removed; use `{ concurrent: false }`. Config files are not looked up from parent directories. [source](https://raw.githubusercontent.com/vitest-dev/vitest/main/docs/guide/migration/index.md)

## Default toolchain
- Use the package manager the lockfile shows (`pnpm-lock.yaml`, `package-lock.json`, `yarn.lock`, `bun.lock`). Do not switch managers.
- Install in CI with the frozen form: `pnpm install --frozen-lockfile`, `npm ci` or `yarn install --immutable`.
- Run project scripts through the manager (`pnpm run <script>`, `npm run <script>`). Read `package.json` for names before guessing.
- Type check with the project's `tsc` setup (`tsc --noEmit`). Lint with the configured tool (ESLint, Biome or Oxlint). Do not add a second one.
- Test with the configured runner (Vitest or Jest). Do not add the other.
- Monorepos: use the task runner already present (`turbo run <task>` or `nx run-many`). Run the tool from the repo root.
