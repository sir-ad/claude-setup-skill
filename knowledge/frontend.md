## Version notes
- **react >= 19**: `ref` is a normal prop on function components, so skip `forwardRef` in new code. Render `<Context value={...}>`, not `<Context.Provider>`. `useFormState` is now `useActionState`. `use()` reads promises and context and may be called conditionally. Ref callbacks may return a cleanup, so write `ref={el => { x = el }}` with braces. [source](https://raw.githubusercontent.com/reactjs/react.dev/main/src/content/blog/2024/12/05/react-19.md)
- **react >= 19**: removed are `propTypes`, `defaultProps` on function components (use default parameters), string refs, legacy context, `ReactDOM.render`, `hydrate`, `unmountComponentAtNode`, `findDOMNode` and `react-dom/test-utils`. Use `createRoot`, `hydrateRoot` and `act` from `react`. `useRef()` needs an argument in the TS types. [source](https://raw.githubusercontent.com/reactjs/react.dev/main/src/content/blog/2024/04/25/react-19-upgrade-guide.md)
- **react >= 19.2**: `useEffectEvent` and `<Activity>` exist, so do not hand-roll refs to dodge effect dependencies. From 19.3, `<ViewTransition />` is available. [source](https://raw.githubusercontent.com/facebook/react/main/CHANGELOG.md)
- **React Compiler 1.0**: it memoizes automatically, so do not add `useMemo`, `useCallback` or `memo` by default. The lint rules ship in `eslint-plugin-react-hooks` `recommended`. The compiler must run first in a Babel pipeline. [source](https://raw.githubusercontent.com/reactjs/react.dev/main/src/content/blog/2025/10/07/react-compiler-1.md)
- **@vitejs/plugin-react >= 6**: the inline `babel` option is gone. For the React Compiler use `@rolldown/plugin-babel`: `plugins: [react(), babel({ presets: [reactCompilerPreset()] })]`, importing `reactCompilerPreset` from `@vitejs/plugin-react`. [source](https://raw.githubusercontent.com/reactjs/react.dev/main/src/content/learn/react-compiler/installation.md)
- **next >= 15**: `cookies()`, `headers()`, `draftMode()`, `params` and `searchParams` are async; await them and type props as `Promise<...>`. Sync access is removed in 16. Codemod: `npx @next/codemod@canary upgrade latest`. [source](https://raw.githubusercontent.com/vercel/next.js/canary/docs/01-app/02-guides/upgrading/version-16.mdx)
- **next >= 15**: `fetch()` and `GET` route handlers are not cached by default, and the client router cache does not reuse page segments. Do not write `cache: 'no-store'` to avoid caching. Opt in with `cache: 'force-cache'` or `dynamic = 'force-static'`. [source](https://raw.githubusercontent.com/vercel/next.js/canary/docs/01-app/02-guides/upgrading/version-15.mdx)
- **next >= 16 (Cache Components)**: with `cacheComponents: true`, data is dynamic by default and caching is opt-in through the `'use cache'` directive with `cacheLife` and `cacheTag`. `experimental.ppr`, `experimental.dynamicIO` and `experimental.useCache` are removed. `revalidateTag(tag, profile)` needs a second argument (`revalidateTag('posts', 'max')`). Use `updateTag` in Server Actions. [source](https://raw.githubusercontent.com/vercel/next.js/canary/docs/01-app/03-api-reference/05-config/01-next-config-js/cacheComponents.mdx)
- **next >= 16**: `middleware.ts` is now `proxy.ts` with `export function proxy(request)`. It runs on the Node.js runtime only. Keep `middleware` if you need the edge runtime. [source](https://raw.githubusercontent.com/vercel/next.js/canary/docs/01-app/03-api-reference/03-file-conventions/proxy.mdx)
- **next >= 16**: Turbopack is the default for `next dev` and `next build`. Drop the `--turbopack` flag; opt out with `--webpack`. Config moved from `experimental.turbopack` to top-level `turbopack`. `reactCompiler` is top-level and stable but off by default. Needs Node >= 20.9 and TypeScript >= 5.1. [source](https://raw.githubusercontent.com/vercel/next.js/canary/docs/01-app/02-guides/upgrading/version-16.mdx)
- **next >= 16**: `next lint` is removed and `next build` no longer lints. Run ESLint or Biome directly (codemod `next-lint-to-eslint-cli`). `serverRuntimeConfig` and `publicRuntimeConfig` are removed; use env vars. Use `images.remotePatterns`, not `images.domains`. Parallel routes need an explicit `default.js`. [source](https://raw.githubusercontent.com/vercel/next.js/canary/docs/01-app/02-guides/upgrading/version-16.mdx)
- **Remix naming**: Remix v2 is frozen. Its successor is React Router v7 framework mode: scaffold with `npx create-react-router@latest` and define routes in `app/routes.ts` with `route`, `index`, `layout` and `prefix` from `@react-router/dev/routes`. [source](https://raw.githubusercontent.com/remix-run/react-router/main/docs/start/framework/routing.md)
- **react-router >= 8**: the `react-router-dom` package is removed. Import `RouterProvider` and `HydratedRouter` from `react-router/dom` and everything else from `react-router`. Packages are ESM-only and need Node >= 22.22 and React >= 19.2.7. Middleware is always on and `context` is a `RouterContextProvider`. [source](https://raw.githubusercontent.com/remix-run/react-router/main/packages/react-router/CHANGELOG.md)
- **remix >= 3**: npm `remix` is Remix 3.0.0, a new framework unrelated to React Router. Do not install it to upgrade a Remix v2 app. [source](https://raw.githubusercontent.com/remix-run/remix/main/README.md)
- **vite >= 8**: Rolldown and Oxc replace esbuild and Rollup. `optimizeDeps.esbuildOptions` becomes `optimizeDeps.rolldownOptions`. The object form of `build.rollupOptions.output.manualChunks` is removed. Default `build.target` is `'baseline-widely-available'` (Chrome 111, Firefox 114, Safari 16.4). `rolldown-vite` was the Vite 6/7 preview package; do not install it. [source](https://raw.githubusercontent.com/vitejs/vite/main/docs/guide/migration.md)
- **astro >= 7**: the Rust compiler is the only compiler and is stricter, so unclosed tags are errors. Markdown and MDX use the Sätteri pipeline, not remark and rehype. `@astrojs/db` is removed. Upgrade with `npx @astrojs/upgrade`. [source](https://raw.githubusercontent.com/withastro/docs/main/src/content/docs/en/guides/upgrade-to/v7.mdx)
- **astro >= 6**: needs Node 22 and uses Zod 4. `Astro.glob()` and legacy content collections are removed. Use `<ClientRouter />`, not `<ViewTransitions />`. [source](https://raw.githubusercontent.com/withastro/docs/main/src/content/docs/en/guides/upgrade-to/v6.mdx)
- **nuxt >= 4**: `srcDir` is `app/`, so components, pages, layouts, composables and `app.vue` live there; `server/`, `modules/` and `public/` stay at the root. `useAsyncData` and `useFetch` return `undefined`, not `null`, for empty `data` and `error`, and `data` is a `shallowRef` (replace the object or pass `deep: true`). Do not target Nuxt 5 yet. [source](https://raw.githubusercontent.com/nuxt/nuxt/v4.6.0/docs/1.getting-started/18.upgrade.md)
- **svelte >= 5**: use runes: `$state`, `$derived`, `$effect`, `$props()` instead of `export let`. Use `onclick={...}`, not `on:click`. Use snippets and `{@render children()}`, not slots. Mount with `mount()`, not `new Component()`. Runes work in `.svelte.js` and `.svelte.ts` files. [source](https://raw.githubusercontent.com/sveltejs/svelte/main/documentation/docs/07-misc/07-v5-migration-guide.md)
- **@sveltejs/kit >= 3**: needs Node >= 22, TypeScript >= 6 and Svelte >= 5.56.4. `base`, `assets` and `resolveRoute` are removed from `$app/paths`. CSRF `checkOrigin` is replaced by `trustedOrigins`. Cookie names must be ASCII and the default cookie `path` is `/`. `getRequest` and `setResponse` are synchronous. [source](https://raw.githubusercontent.com/sveltejs/kit/main/packages/kit/CHANGELOG.md)
- **vue >= 3.5**: `const { foo } = defineProps<...>()` stays reactive in `<script setup>`. Use `useTemplateRef('name')` for template refs. Vue 3.6 is still a release candidate, so do not write Vapor mode code. [source](https://raw.githubusercontent.com/vuejs/docs/main/src/guide/essentials/template-refs.md)
- **@angular/core >= 19**: components are standalone by default, so omit `standalone: true`. Use `standalone: false` only for NgModule-declared legacy components. [source](https://raw.githubusercontent.com/angular/angular/main/adev/src/content/guide/components/anatomy-of-components.md)
- **@angular/core >= 21**: new apps are zoneless. Do not add `provideZoneChangeDetection` or a `zone.js` polyfill unless the app needs Zone. On v20, add `provideZonelessChangeDetection()` and remove `zone.js` from build and test polyfills. [source](https://raw.githubusercontent.com/angular/angular/main/adev/src/content/guide/zoneless.md)
- **@angular/core >= 22**: components with no `changeDetection` are `OnPush`. Write `ChangeDetectionStrategy.Eager` to keep the old behavior. TypeScript < 6.0 is unsupported. `ChangeDetectorRef.checkNoChanges` is removed; use `fixture.detectChanges()`. [source](https://raw.githubusercontent.com/angular/angular/main/CHANGELOG.md)
- **tailwindcss >= 4**: setup is CSS-first. Use `@import "tailwindcss";`, not `@tailwind base/components/utilities`. There is no `tailwind.config.js` by default; load one with `@config "..."` if needed. Customize with `@theme`, `@utility`, `@plugin` and `@variant`. `npx @tailwindcss/upgrade` migrates a v3 project. [source](https://raw.githubusercontent.com/tailwindlabs/tailwindcss.com/main/src/docs/upgrade-guide.mdx)
- **tailwindcss >= 4 tooling**: with Vite use `@tailwindcss/vite` (`plugins: [tailwindcss()]`). With PostCSS use `@tailwindcss/postcss` and drop `postcss-import` and `autoprefixer`. The `tailwindcss` package is no longer a PostCSS plugin. [source](https://raw.githubusercontent.com/tailwindlabs/tailwindcss.com/main/src/docs/upgrade-guide.mdx)
- **tailwindcss >= 4 utilities**: `shadow-sm` became `shadow-xs` and `shadow` became `shadow-sm`. Default border color is `currentColor`, so name a color. `ring` is 1px (use `ring-3` for the old width). The important modifier goes last (`bg-red-500!`). `@apply` in Vue, Svelte or CSS-module `<style>` blocks needs `@reference`. [source](https://raw.githubusercontent.com/tailwindlabs/tailwindcss.com/main/src/docs/upgrade-guide.mdx)
- **shadcn CLI >= 4**: init with `npx shadcn@latest init -t <next|start|vite|react-router|laravel|astro>`. `--base <base|radix|aria>` picks the component library, `-d` takes the defaults without prompts, and `--monorepo` sets up a workspace. Add components with `npx shadcn@latest add <name>` (`-c apps/web` in a monorepo). [source](https://raw.githubusercontent.com/shadcn-ui/ui/main/packages/shadcn/src/commands/init.ts)
- **shadcn with typescript >= 6**: the Vite docs still show `baseUrl: "."` beside `paths`. `baseUrl` is deprecated in TS 6, so write `"@/*": ["./src/*"]` in `paths` and leave `baseUrl` out. [source](https://raw.githubusercontent.com/shadcn-ui/ui/main/apps/v4/content/docs/installation/vite.mdx)

## Default toolchain
- Use the package manager and scripts already in the project (`dev`, `build`, `lint`, `test`). Read `package.json` before guessing script names.
- Framework upgrades: `npx @next/codemod@canary upgrade latest` (Next), `npx @astrojs/upgrade` (Astro), `npx @tailwindcss/upgrade` (Tailwind).
- Check the framework's TypeScript minimum before bumping `typescript`. Angular 22 and SvelteKit 3 need TS 6 or newer.
- Do not add a second bundler, router or CSS framework to a project that already has one.
