## Adapter snippets

### Gemini CLI

Source: https://github.com/google-gemini/gemini-cli (docs/cli/gemini-md.md, docs/reference/configuration.md)

`.gemini/settings.json`. Merge into an existing file; add the key, keep the rest.

```json
{
  "context": {
    "fileName": ["AGENTS.md", "GEMINI.md"]
  }
}
```

Listing both names keeps `GEMINI.md` working. If the project must not carry a settings file, a `GEMINI.md` containing `@./AGENTS.md` also works. Copilot reads GEMINI.md but does not expand `@` in it, so the settings key is the safer default.

### Aider

Source: https://github.com/Aider-AI/aider (aider/website/docs/usage/conventions.md)

`.aider.conf.yml` at the repo root. If `read:` already exists, append AGENTS.md to it and keep every other key.

```yaml
read: AGENTS.md
```

or, merged with an existing entry:

```yaml
read: [CONVENTIONS.md, AGENTS.md]
```

Aider marks `read:` files read-only.

## Scoped-rule mirrors

AGENTS.md has no path scoping, so tools that support globs get mirrors of `.claude/rules/*.md`. The single source is `.claude/rules/`. Do not hand-write mirrors; they drift.

```sh
node "${CLAUDE_SKILL_DIR}/scripts/sync-rules.mjs" --targets cursor,copilot,cline,windsurf
node "${CLAUDE_SKILL_DIR}/scripts/sync-rules.mjs" --targets cursor,copilot,cline,windsurf --check
```

`--check` writes nothing and exits 1 when a mirror would change. Every generated file carries a marker comment. A hand-written file at the same path is never overwritten; the script reports a conflict instead. Only run `--targets` for tools the user selected, and only when `.claude/rules/` has files.

| Tool | Mirror | Frontmatter |
|---|---|---|
| Cursor | `.cursor/rules/<name>.mdc` | `description`, `globs`, `alwaysApply: false`. Plain `.md` is ignored [SEARCH] |
| Copilot | `.github/instructions/<name>.instructions.md` | `applyTo` (glob, comma-separated for several). The name must end in `.instructions.md` [SRC] |
| Cline | `.clinerules/<name>.md` | `paths:` list of globs [SRC] |
| Windsurf | `.windsurf/rules/<name>.md` | `trigger: glob`, `globs:` [SEARCH] |

Windsurf is the least certain row. The docs call `.windsurf/rules/` the fallback and `.devin/rules/` the preferred path after a rebrand to Devin Desktop. The official page was not opened. Limits of 12,000 characters per rule file are also from a search summary.

Cursor note: a forum thread mentions a `.cursor/rules/<name>/RULE.md` folder format. The `.mdc` file form is the one confirmed.

Example Cursor mirror:

```text
---
description: Web app conventions
globs: apps/web/**/*.tsx
alwaysApply: false
---
<!-- generated by claude-setup from .claude/rules/web-next.md; edit the source and re-run sync-rules -->
- Server Actions for mutations. Server Components for reads.
```

## Agent files per tool

Role agents (see `agentic-pipeline.md`) are written once as `.claude/agents/<name>.md`. That file is the source. Facts checked 2026-10-11, same tags as above.

| Tool | Project path | Format | Model field | Reads `.claude/agents/`? |
|---|---|---|---|---|
| Claude Code | `.claude/agents/<name>.md` | Markdown, YAML frontmatter. `name` and `description` required | `model`: `haiku`, `sonnet`, `opus`, full ID or `inherit`; `effort` [SRC] | Source |
| Codex | `.codex/agents/<name>.toml` | TOML: `name`, `description`, `developer_instructions` required | `model`, `model_reasoning_effort`, free-form [SRC] | No |
| Gemini CLI | `.gemini/agents/<name>.md` | Markdown, frontmatter. `name`, `description` required; `tools` list; `kind: local` | `model`, default `inherit` [SRC] | No |
| opencode | `.opencode/agents/<name>.md` | Markdown, frontmatter. `description` required; `mode: subagent`; `permission` | `model`: `provider/model-id` [SRC] | No |
| GitHub Copilot | `.github/agents/<name>.agent.md` | Markdown, frontmatter. `description` required; `tools` | `model`: string or list [SRC] | Yes, CLI and VS Code [SRC] |
| Cursor | `.cursor/agents/<name>.md` | Markdown, frontmatter. All fields optional | `model`: `fast`, `inherit` or an ID [SEARCH] | Yes [SEARCH] |
| Kiro, Devin, Amp | `.kiro/agents/`, `.devin/agents/`, `.amp/plugins/` | JSON or Markdown; Amp uses a code plugin | | Devin imports from `.claude/` [SEARCH]. The others are not targets |
| Cline | none | It has a generic `spawn_agent` tool only [SRC] | | |

No cross-tool standard defines agent files. AGENTS.md is free-form prose, and Agent Skills (`SKILL.md`) carries procedures, not agents [SRC].

Notes:
- Codex spawns a subagent only when the user or an applicable AGENTS.md or skill explicitly asks [SRC: `codex-rs/core/src/tools/handlers/multi_agents_spec.rs`]. The `## Delegation` section in AGENTS.md is therefore required for Codex. Project `.codex/` files load only in trusted projects. Default `max_depth` is 1.
- Codex applies a role file's `developer_instructions`, `model` and `model_reasoning_effort`. A `sandbox_mode` in a role file is not applied: subagents inherit the parent's sandbox [SRC: `codex-rs/core/src/agent/role.rs`]. Write read-only roles as instructions.
- Gemini CLI: subagents cannot call subagents. `@name` at the start of a prompt forces one. `/model` does not change a subagent's model [SRC].
- opencode: the directory is `.opencode/agents/` (plural). The file name is the agent name. Use `permission` (`edit: deny`) for read-only roles, not the deprecated `tools` map [SRC].
- Copilot CLI and VS Code read `.claude/agents/*.md` too. When the same agent ID exists in `.github/agents/` and `.claude/agents/`, the `.github` one wins in the CLI. Do not write both for the same agent. The Copilot cloud agent on github.com reads `.github/agents/`, so write that mirror only when the user uses it [SRC].
- Cursor: whether subagents may nest is unclear (sources disagree). Keep `.cursor/agents/` flat. The skill writes nothing there, since Cursor reads `.claude/agents/` [SEARCH].
- Tool names differ. Gemini CLI uses names such as `read_file` and `grep_search` where Claude uses `Read` and `Grep` [SRC]. The mirror script holds the mapping, so do not copy a `tools:` line between tools by hand.

Generate the mirrors. Never hand-write them:

```sh
node "${CLAUDE_SKILL_DIR}/scripts/sync-agents.mjs" --targets codex,gemini,opencode
node "${CLAUDE_SKILL_DIR}/scripts/sync-agents.mjs" --targets codex,gemini,opencode --check
```

`--check` writes nothing and exits 1 when a mirror would change. Each generated file carries a marker comment. A hand-written file at the same path is never overwritten, and files for agents that no longer exist are removed. `--model-map` writes model values into the mirrors; without it they carry none (see `model-tiers.md`). Run `--targets` only for tools the user selected.

## Hazards

Report these in the plan. Do not fix them silently.

- Legacy single files `.cursorrules`, `.windsurfrules`, `.clinerules` (as a file), `.rules` and `.github/copilot-instructions.md` come before AGENTS.md in Zed's first-match list. Zed Agent reads that file and skips AGENTS.md [SRC].
- Do not create `.junie/AGENTS.md`. If present, Junie uses it exclusively and ignores the root file [SEARCH].
- Kiro: a community issue reports a symlinked AGENTS.md not loading. Use a real file.
- Claude Code: AGENTS.md alongside a CLAUDE.md without `@AGENTS.md` is never read. Adding a personal CLAUDE.local.md has the same effect.
- Copilot chat on github.com and Eclipse read only `.github/copilot-instructions.md`, not AGENTS.md [SRC]. The gap is accepted. A pointer sentence would not be followed as an import there. If the user wants coverage, offer a full copy with a "generated from AGENTS.md" header.
- VS Code Local agent needs the setting `chat.useAgentsMdFile`. Nested AGENTS.md files are off by default (`chat.useNestedAgentsMdFiles`) [SRC].
- Codex skips project docs in untrusted projects and stops at 32 KiB combined [SRC].
- Prose such as "See AGENTS.md" in another tool's file is sent verbatim. Models may not follow it. Use a real import or config key where the tool has one.
- opencode does not parse `@file` references inside AGENTS.md [SRC].

## Not written by default

`.github/copilot-instructions.md`, `.cursorrules`, `.windsurfrules`, `.clinerules` as a file, `.junie/AGENTS.md`, Roo Code files, symlinks (`ln -s AGENTS.md CLAUDE.md`). A symlink is opt-in on request: Windows needs privileges, Kiro may not follow it, and Claude Code's Edit and Write refuse to write through one.
