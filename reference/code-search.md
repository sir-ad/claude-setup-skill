# Code search

How agents find code in a generated project, and the optional tools the skill can offer.

## Default

The default is agentic search plus a generated repo map. No index, no embeddings, no service.

- **Agentic search.** Claude Code's search tools find files by pattern and search content by regex. Anthropic describes the pattern as a hybrid: CLAUDE.md is placed in context up front, and primitives such as glob and grep retrieve the rest just in time. ([context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) , [how Claude Code works](https://code.claude.com/docs/en/how-claude-code-works))
- **Repo map.** `docs/project-structure.md` is generated by `scripts/graph.mjs`. It holds a Mermaid module graph, entry points, central modules and a budgeted list of top files with exported symbols. The explorer agent reads it first, so it can aim its greps. The generated sections sit between `<!-- claude-setup:begin graph -->` and `<!-- claude-setup:end graph -->`, and `--update` refreshes only those.
- **Why this shape.** An index must be built, can drift out of sync with the code, and raises questions about where the index lives. The skill avoids all three by default.

Two claims here come from search summaries, not from Anthropic's docs. Treat them as [SEARCH]:
- [SEARCH] Early Claude Code used RAG with Voyage embeddings and dropped it, for the three reasons above. ([Latent Space interview](https://www.latent.space/p/claude-code))
- [SEARCH] Boris Cherny, Feb 2025: "Claude Code doesn't use RAG currently. In our testing we found that agentic search out-performed RAG for the kinds of things people use Code for." ([Hacker News](https://news.ycombinator.com/item?id=43164253))

Anthropic's own docs do not say this. They say large codebases can add a code-intelligence (LSP) plugin for go-to-definition and find-references, and that an organization with an existing code search or RAG index can expose it as an MCP tool. ([large codebases](https://code.claude.com/docs/en/large-codebases))

## Repo map, in short

Aider's repo map is the model for the generated one: a concise map of files and key symbols. Aider parses definitions and references with tree-sitter, ranks files with a graph algorithm (PageRank), and fits the top of the ranking into a token budget (`--map-tokens`, default 1k). ([Aider docs](https://aider.chat/docs/repomap.html)) `graph.mjs` is simpler: it parses imports with regexes, ranks by in-degree and a small PageRank, and has no dependencies. It will miss dynamic imports and generated code. Say so in the file when it matters.

## Optional MCP servers

Offered only for large or typed repos, and only when the person asks or says yes in the plan. Facts are from each project's README. Maintenance status was not checked, so look at the repo before you adopt one.

| Server | What it does | Runs where | Needs |
|---|---|---|---|
| [oraios/serena](https://github.com/oraios/serena) | Symbol-level search, edit and refactor through language servers (40+ languages) or a paid JetBrains plugin. | Local | No API key. `uv tool install -p 3.13 serena-agent`, then `serena init`. GPL-3.0. |
| [CodeGraphContext](https://github.com/CodeGraphContext/CodeGraphContext) | Indexes code into a graph database (FalkorDB Lite by default, or KuzuDB or Neo4j) and serves it over MCP and a CLI. | Local | No key. No remote service required. |
| [zilliztech/claude-context](https://github.com/zilliztech/claude-context) | Semantic and hybrid (BM25 plus dense) search. | Embeddings from a provider, vectors in Milvus or Zilliz Cloud | An embedding API key (OpenAI by default; VoyageAI, Gemini and Ollama are listed) and a Milvus or Zilliz Cloud database (`MILVUS_ADDRESS`, `MILVUS_TOKEN`). `npx @zilliz/claude-context-mcp@latest`. |

With claude-context, code chunks go to the embedding provider unless you use a local one such as Ollama. State that when you offer it. Suggest it only if the person already has a key and a vector database.

Also seen, not offered by default: [probelabs/probe](https://github.com/probelabs/probe) (AST-aware search, no index, MCP mode) and [code-graph-rag](https://github.com/vitali87/code-graph-rag) (needs Docker and Memgraph).

## Adding one to `.mcp.json`

The file lives at the project root, not in `.claude/`. The top key is `mcpServers`. A stdio server has `command`, `args` and `env`. An entry with `url` and no `type` is a config error. Secrets go in `${VAR}` references, never literals. ([MCP docs](https://code.claude.com/docs/en/mcp))

```json
{
  "mcpServers": {
    "claude-context": {
      "command": "npx",
      "args": ["@zilliz/claude-context-mcp@latest"],
      "env": {
        "MILVUS_ADDRESS": "${MILVUS_ADDRESS}",
        "MILVUS_TOKEN": "${MILVUS_TOKEN}"
      }
    }
  }
}
```

The command and the two Milvus variables come from the claude-context README. Add the embedding key variable that README names, again as a `${VAR}` reference. For serena and CodeGraphContext, copy the `command` and `args` from their READMEs. Do not guess them. `claude mcp add --scope project` writes the file for you. ([MCP docs](https://code.claude.com/docs/en/mcp))

Approval: Claude Code asks before using a project-scoped server. A committed `.claude/settings.json` approval is ignored in an untrusted folder. In `claude -p` and cloud sessions, project servers load without a prompt. If `.mcp.json` already exists, add an entry and leave the others alone. Other agents (Codex, Cursor) use their own MCP config, so say which one you changed.

## What the skill will and will not do

- It never installs or configures any of these without a yes.
- It never sends code anywhere by itself. The default needs no network. A server that uses a remote embedding or vector service is named as such before the question.
- It does not write fake "semantic search" claims into AGENTS.md. If no server is set up, nothing about one appears in the generated files.
